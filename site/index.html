How it works

No servers, no queues, no headless browsers. One Worker, one D1 database, and the public HTML pages MyAnimeList already serves to everyone.

01

Fresh? Serve from D1.

Cached data within TTL (6 h for most resources, 2 h for user lists) is returned straight from the edge database — MyAnimeList is never touched.

02

Miss? Fetch once, parse, persist.

A cache miss fetches the public page a single time, runs a pure HTML parser, validates the document, and stores the normalized result. Refresh locks stop thundering herds.

03

Upstream down? Serve stale.

If a refresh fails and a stale copy exists, you still get a 200 — flagged with meta.stale: true instead of an error. Valid data is never replaced by a suspicious document.

Rate limits — two per-IP windows enforced globally across all routes, mirroring Jikan's own policy: 30 req / 10 s burst and 60 req / min sustained. Exceeding either returns 429 with a Retry-After header.

Migrating from Jikan?

One click, one paste. The button below copies a ready-made prompt for your AI coding agent (Claude Code, Cursor, Copilot…) that ports a project from api.jikan.moe/v4 to jikan-edge — envelope, naming, pagination, rate limits, everything.

before https://api.jikan.moe/v4/anime/1 → mal_id, images.jpg.image_url, aired.prop.from.year
after https://jikan.lucashdo.com/v1/anime/1 → malId, images.medium, aired.from

Not a drop-in swap, and it isn't trying to be: the envelope is { data, meta }, fields are camelCase, genres and studios carry their malId, and dates come split into { from, to, string }. The prompt covers all of it, plus pagination, 429 handling and the routes we don't serve — and asks the agent to verify every endpoint against the live API.

Not affiliated with MyAnimeList or Jikan. All data comes from publicly accessible MyAnimeList pages, cached aggressively and rate-limited to keep upstream load minimal. If you are MyAnimeList and have concerns, please open an issue.
