# Cloudflare Workers docs: Static Assets, Headers

> Fetched 2026-10-11 · Read because serving `site/openapi.json` as a static asset bypasses the
> Worker, and with it the Worker's `Access-Control-Allow-Origin: *`.

## What it says

Content type comes from the file extension at upload:

> "Wrangler automatically determines the MIME type of the file, based on its extension."

Custom headers for assets live in a `_headers` file in the assets directory:

> "This file will not itself be served as a static asset, but will instead be parsed by Workers and its rules will be applied to static asset responses."

> "Custom headers defined in the `_headers` file are not applied to responses generated by your Worker code"

The CORS recipe adds `Access-Control-Allow-Origin: *` under a URL pattern.

## What it does not say

- That assets get no CORS header by default. Measured instead with `wrangler dev --local` (wrangler
  4.127.1) on a copy of this repo: `GET /openapi.json` came back `200`, `Content-Type:
  application/json`, an `ETag`, and **no** `Access-Control-*` header and no `X-Request-Id` (the
  Worker did not run); `GET /health` on the same server carried three `Access-Control-*` headers.
  `site/` has no `_headers` file today.
